# Feature parity for authored styles

TypeLab should let someone start with a recognizable style, change its construction and details, and export a coherent family. Weight masters establish one part of that contract. Near parity also requires alternate drawings, named letter parts, finishing effects, and authored accent marks. These need different representations; making every control another generic outline deformation would repeat the failures that prompted this migration.

This is an implementation map, not a claim that the proposed features are available. It audits the current `weight-masters` worktree against the intentions recorded in [parameter specifications](../../shared/params/spec.ts), [shape options](../../shared/params/options.ts), [traits](../../shared/traits.ts), and the [original architecture proposal](proposal.md).

## Current baseline

The parameter specifications define 60 primary controls and 40 nested control entries; `slice` and `stencil` appear in both groups. Different construction modes intentionally expose different subsets.

- All 22 outline families have compatible weight masters for 127 characters, within their [documented ranges](weight-masters.md). A family can contain original upstream weight changes, newly authored local variants, or existing bundled weight drawings. These are not interchangeable provenance claims.
- A source style supports weight plus width, height, x-height, extenders, descender, slant, rotation, mirror, side bearings, tracking, and word spacing. Historical `outline-v1` references support the same list without weight. The [capability gate](../../shared/source/capabilities.ts) exposes additional controls and named options only when the saved program includes their reviewed implementation.
- All 22 current programs have joint weight/width drawings; see the [width authoring results](width-masters.md). The latest 18 families use conservative local ranges with exact neutral subdivisions and compatible existing feature endpoints. Their optical review and parameter sweeps are deferred. Historical programs retain their prior width interpretation. Heights use an increasing piecewise affine map with exact curve subdivision and special handling for `i`/`j` dots; optical redesign at extreme proportions remains unfinished.
- H crossbars now cover all 22 styles across their weight/width grids. Hearth and Couture also have A crossbars, R leg length, and c terminal length. These appear while editing a covered letter alone. The latest nine H constructions retain the existing point bases; their optical review is deferred.
- All 22 current programs have Solid, Shadow, Outline, seven pattern materials (Pixels, Hexagons, Dots, Halftone, Lines, Blobs, Liquid), Slice, Hand-drawn, and Rough edges. Points retains the clean editable drawing. Outline, patterns, and texture use fractional CFF export; typed failures retain recovery and an explicit export error. The previous [finish review](../../tools/masters/finish-design.md) covers Shadow/Slice. The newer effects have bounded implementation checks; their full interaction and visual review is deferred. Inline and Wire remain unfinished.
- Component Size covers 374 explicitly bound groups across 286 glyphs: i/j tittles and detached punctuation dots in every style. Original is an exact no-op; other sizes preserve the body, advance, and component ownership of saved Points. Each dot in an ellipsis, colon, or division sign has its own anchor. Round/Square forms remain separate work.
- Source Mono now translates letters into a common advance cell, preserving their curves and existing equal-advance families. A saved spacing frame preserves the original advance through full Mono, Points edits, and reopening. Spaces, nonbreaking spaces, Shadow, and per-letter overrides share the parent cell. Optical spacing review and full interaction testing remain deferred.
- Source text placement and OTF now share minimum and rounded advances, including narrow punctuation, spaces, and nonbreaking spaces. Tracking changes placement without changing Points. Source Rotation displays the actual clockwise angle relative to its saved neutral frame; this corrects the displayed units without changing saved geometry. Seven [spacing](../../tests/source-spacing.test.ts) and [Rotation](../../tests/source-rotation-display.test.ts) checks cover these contracts and the actual Adjust actions.
- Source Adjust choices use a [shared recipe resolver](../../shared/source/trait-recipes.ts). Normal width selects the authored neutral; weight and lowercase choices describe changes from the original style; slant choices add the stated angle; Slice opens a visible half-range gap. Menus omit duplicate results, while carried intents remain resolvable. Thirteen [recipe and action checks](../../tests/source-traits.test.ts) cover all 22 styles' neutral inputs, custom saved frames, historical width programs, source-to-generated style switches, and saved designs.
- The legacy renderer remains available for saved designs and generated stroke/block/arc styles. “Legacy only” below means unavailable on the new source-backed styles, not deleted from the entire application.
- Accented letters: every current program pins [authored marks](source-marks.md) for the 134-character inventory, composed on the edited base letters and exported on request.
- Alternate letters: twelve [authored forms](source-forms.md) in seven styles (two-storey and one-storey a and g, barred I, plain l, curved-leg R, long-tail Q), picked per letter on the Letters page, with their own weight/width grids and Points edits.
- Source glyphs currently return `blankParts()` and one `drawn` stroke in [source evaluation](../../shared/source/instance.ts). The inspector cannot reliably target a source's stem, terminal, serif, crossbar, or tail. Reviewed dot identities are the limited exception in [source features](../../shared/source/features.ts).

## Shape and construction parity

| User intent / existing controls | Current source support | Concrete implementation and release condition |
| --- | --- | --- |
| Lighter/heavier letters: `weight` | Available across all 22 families; ranges vary | Keep the compatible-master path. Extend ranges only through additional authored endpoints and visual review, not extrapolation. Every later feature must be checked at the supported weight extremes. |
| Condensed/expanded letters with consistent strokes: `width` | Joint grids in all 22 current programs; latest 18 local families await optical review | Mainline/Parlance cover 75–150, Gumdrop 75–125, Cotton 85–115. New ranges vary by family from 95–105 to 85–115. Existing feature endpoints share the same field and subdivision. Dispatch/Kernel retain equal advance ratios. Old documents retain their pinned range or stretch interpretation. |
| Proportions: `height`, `xHeight`, `extenders`, `descender` | Available as bounded geometric maps | Keep the maps as a useful baseline. Add feature-aware dot/mark placement and optical corrections for compressed shoulders, joins, overshoots, and hairlines. Author height × weight interaction drawings where a smooth map retains topology but produces poor type. |
| Pose: `slant`, `rotation`, `mirror` | Available; source Rotation units reflect its pinned 90° total range | Retain explicit geometric transforms and metrics rules. Source rotation is relative to `freeAt.rotation`, so its default range is −45° to +45° clockwise; legacy generated letters retain −180° to +180°. Treat a true italic design as a separate form/style, since slant alone does not draw italic letterforms. |
| Thick/thin relationships: `contrast`, `vWeight`, `hWeight`, `strokeWeights` | Legacy only | Author paired stem/hairline boundary spans and contrast endpoints with weight interaction. Start with ordinary contrast changes in Mainline, Hearth, and Couture. Reverse contrast needs its own designed endpoint; independently offsetting horizontal and vertical contours is insufficient. Per-stroke edits use stable feature IDs. |
| A narrowed waist: `pinch`, `pinchPos` | Legacy only | A smooth, shared deformation field can supply small changes while keeping connected ink together. Bind the field to authored stem regions and preserve minimum stem/counter widths; larger changes require endpoint drawings. |
| More internal space/open ends: `counter`, `aperture` | Legacy only | Counter edits move corresponding inner and outer boundaries while preserving intended stroke thickness. Aperture edits move named terminal regions with a required opening. Check `e`, `a`, `s`, `c`, `G`, and heavy/narrow combinations, rather than scaling every hole. |
| Bowl shape: `bowlForm`, `curve`, `squareness`, `boxRound`, `chamfer` | Legacy only | Give a bowl its own outer/inner spans, extrema, and connection ports. Use compatible rounded/squared endpoint drawings for continuous changes. A box or faceted construction that changes topology is a discrete alternate. Do not fit all bowls back to a universal oval. |
| Bowl/stem relationship: `bowlJoin`, `overlap` | Legacy only | Bind both sides of each join to the same attachment region. Curved/square joins are authored patches or alternates. Maintain join depth and counter clearance throughout the weight range; overlapping source contours are allowed and must be evaluated as filled ink. |
| Corners and pointed joins: `roundness`, `innerRound`, `apex`, `joinRound`, `steps`, `cornerSteps`, `corners`, `innerCorners`, `bends` | Legacy only | Annotate actual corners and their adjacent curve spans. Compile rounded/chamfered/stepped patches offline with compatible subdivisions. Preserve true curves and thin serifs. Sharp-to-round diagonal constructions can use dedicated form variants when corner patching is insufficient. |
| Ink traps/join thinning: `joints` | Legacy only | Author trap mouths, depths, and protected attachment spans. A trap is a local structural feature, not the same operation as a decorative stencil cut. Verify that minimum joins remain connected at the heaviest and narrowest settings. |
| Tail and bar placement: `tail`, `crossbar`, `barGap`, `barEnds` | H crossbar in all 22 styles; Hearth/Couture A crossbar and R leg | Review the latest nine H ranges. Extend authored attachments, tangents, and tips to `Q`, `y`, `g`, `j`, `f`, `t`, and `e`, plus punctuation tails. Gap and Through remain unavailable; deliberate gaps require explicit topology changes. |
| Dot style and size: `dots`, `dotSize` | Per-letter Size for 374 i/j and punctuation components across all 22 styles | Add style-owned round/square variants and marks. Detached punctuation dots are explicitly bound; comma tails and punctuation bodies stay unchanged. Serenade j has a bound separate dot despite overlapping vertical extents with its flourish. Full optical and mixed-parameter review of Size is deferred. |
| Stroke ends: `terminal`, `terminalForm`, `terminalRun`, `terminalLength`, `terminalCurl`, `terminalEnds`, `terminalCurls`, and terminal detail sliders | Partial: c terminal length in Hearth/Couture | Extend authored terminal regions and attachment ports to more characters and styles. Length, curl, flare, and cut changes need compatible patches and a palette belonging to each style. The existing 14 terminal subforms remain a coverage target. |
| Serif construction: `serif`, `serifShape`, `serifTip`, `serifBase`, `serifSides`, `serifInner`, `serifBalance`, `serifTops`, `serifArms`, and their size/detail sliders | Legacy only | Add serif feature groups with stem ports and explicit inner-gap constraints. Start with size, thickness, bracket, and tip changes on existing serif families. Serif on/off and slab/wedge/diamond conversions require complete reviewed patches or alternate drawings, including exceptional letters and punctuation. Weight × serif interactions must be authored together. |
| Alternate letters: `story`, `aForm`, `gForm`, `iForm`, `jForm`, `kForm`, `mForm`, `qForm`, `rForm`, `sForm`, `yForm`, `apexForm`, `diagonals` | [Twelve forms](source-forms.md) of a, g, I, l, Q and R in Mainline, Parlance, Compass, Cotton, Vellum, Hearth and Kernel; picked per letter in place of Letter a, g, I/l, Q and R; the rest legacy only | Discrete forms with their own weight/width grids and point identities are in place; switching restores each form's Points edits. The upstream alternates are used up: further forms are new drawings. Next, the other 15 styles' `a`/`g`/`I`/`l`/`Q`/`R` (Jotter, Boardwalk and Serenade in their own hand), then `k`, `s`, `y`, `J`, `M` and the apex. Give forms their own mark ports and feature bindings; never interpolate between unrelated contour structures. |
| Handwritten construction: `cursive` | Legacy only; script source styles retain their original drawings | Separate italic/form selection from entry/exit extensions. Authored script connectors need consistent attachment heights and contextual pair behavior. The existing threshold-based variant switch is useful UI history, not a complete joining model. Begin with Jotter/Boardwalk/Serenade rather than promising joined versions of every style. |
| Handmade variation: `wobble`, `rough` | Available in all current programs | [Continuous seeded fields](source-texture.md) move the whole ink together, with separate long and short wavelengths, bounded displacement, cubic fitting, and recoverable complexity limits. New controls start at zero. Underlying field invertibility does not replace the deferred review of fitted geometry and text. |
| New construction systems: `build`, `blockForm`, `cellJoin`, `gridRows` | Existing generated modes, separate from source masters | Keep their purpose-built generators and compile to the common evaluated outline/metrics contract. A block or arc alphabet is a deliberate construction choice. It should not silently replace a selected source while pretending to retain that source's design. |

The width-axis inventory is local evidence from [pinned upstream metadata](../../tools/masters/upstream.json). Available upstream axes are a starting point for authoring, not proof that their full range transfers cleanly to TypeLab's edited outlines.

## Finishes, language coverage, and workflow parity

| User intent / existing controls | Current source support | Concrete implementation and release condition |
| --- | --- | --- |
| Spacing: `letterSpacing`, `wordSpacing`, `sideBearing`, `mono` | All four available in current programs; Tight/Normal/Loose Adjust choices work | Preview pen steps use the exported integer advances, floored at 20 units for glyphs and 40 for spaces. Line bounds end at the last glyph's raw advance, excluding trailing tracking/flooring. Mono uses the widest authored advance and preserves bearing balance through translation. Its saved frame retains reversible Points editing. Review repeated punctuation, scripts, mixed controls, and export during the testing pass. Compact monospacing needs authored width corrections. Tracking is not pair kerning. |
| Decorative material: `fill`, `module`, `dotGain` | Solid, Shadow, Outline and all seven pattern materials across all 22 styles; active pattern controls available | [Source finishing](../../shared/source/finish.ts) applies a pinned policy after geometry and pose. The legacy fixed-sampling adapter lost hairlines, so source effects use adaptive curves and explicit dimensions. Outline and seven pattern materials now have bounded geometry and fractional export. Full thin-stroke, counter, and interaction review remains deferred. Inline and Wire remain separate implementation work. |
| Horizontal cuts: `slice`, `slicePos`, `sliceRound` | Available across all 22 styles | The pinned source policy opens a gap up to 14% of cap height, with the split at 12–88% of cap height. Size zero is identity. Upper ink moves up and lower ink stays; sharp cuts preserve every piece, including punctuation. New-corner rounding is bounded against other boundaries and counters. Ascent includes the largest per-letter gap; face metrics and editable Points stay unchanged. |
| Structural stencil: `stencil`, `stencilPos`, `stencilRound`, `joinGaps` | Legacy only | Author cut corridors at named joins, with bridges and counter-opening intent. A screen-space slice cannot stand in for stencil construction. Store expected connectivity for each stencil form and keep per-join controls addressable. |
| Accented letters and dotless `i` | All 134 `ACCENTED` characters in all 22 current programs, in font, family, and specimen exports when asked | [Authored marks](source-marks.md) sit at explicit ports on the base letter as drawn, including its Points edits, own settings, weight, width, heights, pose, Mono, and finish. `ı` and the accented `i` drop only the tittle. Bulwark's marks and some of Cathedral's, Funnies's, and Gumdrop's are local constructions. The editor's preview does not show accented letters; legacy styles never did. Optical review at weight/width extremes and mixed heights remains, as does clearance between neighbouring wide marks (Gumdrop's capital I accents overhang, as upstream). |
| Edit a letter or named part; propagate a related edit | Per-letter supported parameters and Points edits work; semantic part editing unavailable on sources | Extend the inspector's existing scopes with reviewed feature bindings. Current [edit transport](../../shared/source/edit-transport.ts) tracks authored segment locations, including curve splits; preserve that work. Bind new point edits to a source/form/feature frame where possible. Topology-changing edits explicitly reduce the affected capability instead of causing unrelated parts to move. |
| Families, current-instance export, saved designs, history | Weight families and current instances supported; only authored family weights/orientation; old source snapshots retained | Keep one evaluator for preview, OTF, and SVG. Add real italic family members separately. Carry features and composites through family export, preserving local overrides. Old saved source interpretations remain pinned; adopting a richer program is an explicit revision. Round-trip exported outlines, metrics, names, and character coverage. |
| Style filters, traits, random combinations, personality macros | Source-aware weight, width, lowercase, slant, and Slice recipes; unsupported whole-font traits filtered; source geometry neutralizes the old personality macros | Application, previews, labels, and Shuffle share the same recipes. Source weight choices are Lightest/Lighter/Original/Heavier/Heaviest rather than unsupported Thin/Black claims. Lowercase choices describe smaller/original/larger proportions rather than claiming cap height. Preserve saved raw values. Appearance/search tags now use the original appearance and authored coordinates; the personality macros can later become curated recipes over authored features. |

These workflow findings are grounded in [editor state](../../client/state/editor.ts), [inspector targeting](../../client/components/Inspector.tsx), [family selection](../../shared/family.ts), and [export construction](../../server/export.ts). No current GSUB/GPOS shaping or pair-kerning implementation was found in the application evaluator/export path; contextual scripts and exported stylistic sets would therefore be additional work, not a switch to enable.

## The next source representation

Extend the source program, keeping immutable drawings and the existing editor. The missing data belongs in authored assets; runtime should evaluate it rather than repeatedly infer anatomy.

| Program data | Ownership and purpose |
| --- | --- |
| Discrete forms | Each glyph form owns compatible curves, metrics, and variation data. Forms with different topology never share a point-interpolation space. |
| Joint variation cells | Weight, width, contrast, and selected proportion axes use explicit design coordinates and reviewed interpolation regions. Interaction masters carry changes that are not additive. Avoid an uncontrolled Cartesian product of every slider. |
| Semantic features | Stable IDs bind boundary spans, local frames, attachments, and clearance measurements. Examples: `R.leg`, `a.aperture`, `i.dot`, `H.crossbar`, and inner serif tips. These describe existing curves without replacing them with a skeleton. |
| Feature recipes | Small compatible patches or shared deformation fields implement a named edit. Their dependencies specify which weight/width cells and forms were authored. |
| Components and anchors | Base letters, marks, dotless forms, and script connectors share explicit placement rules and variation coordinates. Optical exceptions remain data. |
| Finish pipeline | Ordered effects consume the evaluated base outlines, with deterministic seeds, approximation tolerance, metrics behavior, and complexity limits. An effect may intentionally change topology. |
| Capability manifest | Each control declares affected glyphs/forms, supported coordinates, dependencies, and unavailable reasons. Panel, inspector, traits, preview, family export, and validation read the same result. |

Evaluate in this order: choose form → evaluate joint masters and supported proportion transforms → apply authored feature edits and saved local edits in their defined frames → place components from the resulting anchors → apply pose and metrics → apply finishing effects → project to the output format. This lets accent marks retain their designed shape when the base's x-height changes. Feature recipes must declare their frame and ordering; swapping two operations is not assumed harmless.

An edit's allowed interval is the intersection of the affected glyphs' supported regions. Keep saved values in stable design coordinates. Report a limiting feature rather than silently clamping individual letters to different results. Preserve the historical `outline-v1` and `masters-v1` interpretations while publishing richer programs under a new version.

## Delivery order

1. **Make supported controls predictable.** Keep spacing, Rotation, and Adjust choices on their verified units. Align appearance/search tags with each style's original appearance and actual changes, rather than the old raw slider thresholds. Prove translation-only Mono at 0, 0.5, and 1 before publishing it; do not squeeze wide letters into a narrow cell. Continue reviewed source finishes as independent policies.
2. **Add components and complete real proportions.** Review the 374 component identities and clearance-limited sizes; add style-owned round/square forms. Serenade's overlapping `j` is explicitly bound. Use those bindings for dotless `i` and authored Latin-1 marks. Review the new width drawings across all 22 families, then finish bar, tail, aperture, and terminal coverage with their weight/width interactions before enabling whole-font controls.
3. **Restore character and construction choices.** Add style-owned `a`/`g`/`I`/`l`/`Q`/`R` forms, then expand to the original alternatives. Author contrast, terminals, serif palettes, corners, and ink traps in family groups. Complete mark coverage and direct feature editing alongside them.
4. **Make expressive systems deliberate.** Add reverse contrast, major serif conversions, script connections, and deeper hand-drawn variants as designed style programs. Preserve block/arc modes. Extend successful recipes to all applicable families; record intentional inapplicability separately from unfinished work.

Track progress by **style × feature × affected character coverage**, including interactions, preview, local edits, save/reopen, and export. Counting visible sliders alone would conceal unchanged punctuation, broken heavier forms, or a control that only works on one sample letter.

The preset audit found that raw Normal width 0.52 selected coordinate 114 in Mainline/Parlance and raw Regular weight 0.44 selected different weight classes. The resolver now uses the authored width neutral and offers relative weight choices around the original. Lowercase presets select 88% of original x-height, the original, or 30%/60% of the gap toward cap height; the last is labeled Largest because the pinned map does not reach cap height. Slant choices preserve the original or add −7°, +7°, or +15°, omitting directions outside the saved range. Slice selects 0.5 at the middle position with sharp contacts, currently a 7%-cap gap. Legacy recipes and loaded saved values remain unchanged.

Neutral, unsupported, and endpoint-equivalent choices retain the cached original card parameters and browser renderer. Source recipes omit unsupported legacy reset fields, so None and Normal Spacing also remain neutral. The initial source cards and filter chips now use [immutable neutral preview fonts](../../shared/source/preview-catalog.ts) generated by the same source evaluator as the editor, including the master repairs. The current 22 font files total 2,601,292 bytes after width-basis publication. The earlier preview generation was deterministic; repeat-generation checks for this batch are deferred. Browser layout checks and the prepared focused tests remain deferred to the testing pass. New source programs or style presets must regenerate these previews with `tools/authored/build-previews.ts`.

Source appearance now retains each style's original tags and adds Narrower/Wider and Lighter/Heavier from its authored coordinates. Weight tags use the actual nearest OpenType class. Search still includes the style's description and genre; it is not a strict facet filter. Adjusted style cards load master geometry near the viewport to avoid fetching every full family at once.

The [translation-only Mono prototype](../../tools/masters/prototype-mono.ts) compares preserving bearing balance with centering the ink, at amounts 0, 0.5, and 1. Its 3,810 checks cover all 127 glyphs in Mainline, Couture, Serenade, Dispatch, and Kernel; every changed coordinate differs only by the declared horizontal translation. With a 4%-cap side allowance, the common cell is 1.59 times the median alphabet advance in Mainline, 1.71 in Couture, and 2.81–3.56 in Serenade, depending on centering. It also widens the existing 600-unit Dispatch and Kernel cells. This proves the operation can preserve curves, but not that one computed cell is a good spacing design. The published Mono policy consequently uses the widest original advance, preserves existing equal-advance families, and allows explicit ink overhang instead of widening cells from script flourishes. Optical spacing review remains deferred. Run `node --import tsx tools/masters/prototype-mono.ts`; add `--render` for comparison sheets.

## A distinctive product built from this work

The useful distinction is a font editor that understands the feature being changed and carries that intention across the family.

- **A style-owned detail palette.** “Soft terminals” or “open counters” selects drawings and motions authored for the chosen family. The existing trait cards become reliable previews of coherent alternatives rather than bundles of unrelated numeric settings.
- **Edit one relationship, preview its family.** Move an `R` tail departure or alter an `a` opening and immediately inspect the same intention at light/heavy weights and in alternate forms. The current inspector, family preview, and authored point provenance provide the starting structure.
- **Explain the actual limit.** When a request would close an opening or detach a serif, highlight that feature and the supported boundary. Use this sparingly: ordinary controls should have generous reviewed ranges, not interrupt every drag.
- **Compose with the letters already edited.** Accents, dots, and compatible script attachments follow the user's base-letter changes. Preview and exported fonts retain the same relationships.

These are achievable extensions of existing UI and authoring work. They depend on explicit feature data and reviewed variants, not on a new universal letter-reconstruction algorithm.

## Validation limits

For structural features, check the rendered filled ink, named attachments and clearances, finite metrics, and the intended direction of change. For decorative effects, use their declared topology and minimum-detail rules instead of demanding the base glyph's component count. Review specimens at text and display sizes, including all affected glyphs, punctuation, marks, and interacting axis boundaries.

Sampled topology checks catch regressions; they do not prove every intermediate drawing is good type. Positive deformation maps preserve topology but cannot establish optical quality. Upstream masters provide designed variations, but transferring them to edited source geometry still needs review. The asset recipe, provenance, repairs, tested domain, and visual evidence should accompany each published capability, as they now do for weight masters.
